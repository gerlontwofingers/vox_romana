Appendix: Notes & Constraints
- Do not modify source code without an explicit instruction from the implementer.
- Editor must be non-interactive; retry cap = 3; provide targeted remediation hints when rejecting/generated chunks.
- Per-agent notes are private by default and summarized/sanitized by the Conductor before persistence.
- DeepSeek is the default fact-checker; Google CSE is optional and requires env keys.
- Speaker clarity & dialogue guidance:
  - Problem: Historically, it can be difficult to tell which characters are speaking when only text is available. In audio/visual media, speaker changes are made obvious with audio cues, camera cuts, or visual labels; plain text can lose that clarity.
  - Recommendation for agents: Prefer explicit speaker identification in generated chunks. When dialogue is ambiguous, insert one of:
    - Short speaker tags (e.g., "Alex:", "Host:") at the start of lines.
    - Brief scene direction or stingers (e.g., "Announcer (V.O.):", "Cut to the field reporter:") between chunks.
    - Bracketed actions or audio cues (e.g., "[music swells]", "[door slams]") to signal transitions.
  - Radio-style inspiration: Use conventions from old radio broadcasting — announcer lead-ins, clear speaker cues, and short sonic markers — to make speaker turns unambiguous in audio renderers and for later TTS alignment.
  - Editor behavior: When reviewing dialog chunks, prefer adding or requesting explicit speaker labels or scene cues rather than merging ambiguous lines. If a chunk lacks clear speaker turns, mark it as "requires speaker disambiguation" and suggest concrete insertions.
 - Director outline & cast awareness:
   - Role: The `Director` agent maintains an evolving show outline derived from instructions given to the Director. The Director must make the current outline available to the entire cast.
   - Outline propagation: Any time the outline is created or updated — including changes triggered by the Orchestrator or the Editor — the Director must broadcast a concise outline snapshot to all character agents, the Conductor, and Editor. The snapshot should include `outline_id`, `version`, `timestamp`, `summary`, and `changed_sections`.
   - Outline structure: Represent the outline as an ordered array of `sections`, each with `id`, `title`, `expected_duration`, `key_beats`, `speaker_assignments`, and `acceptance_criteria`.
   - Cast awareness: Character agents must check incoming outline snapshots and update their internal state to match assigned beats. If a character cannot comply, it must report a short `issue` message to the Director with proposed remediation text.
   - Interaction with Editor/Orchestrator: When the Editor or Orchestrator requests changes (e.g., trimming, merging, inserting, reordering), Director updates the outline version and rebroadcasts to the cast. Editor reviews should reference the outline `version` they validated.
   - Persistence and audit: The Conductor should persist outline snapshots in studio memory for rehearsal and audit trails.
   - Implementation notes: Use idempotent JSON snapshots and version numbers. Keep messages small; favor `summary` for human readability and `sections` for machine validation.
